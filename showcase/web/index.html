Reward path

The Go server calls the privileged showcase_result RPC with a server-only secret. Nakama writes the leaderboard, wins, tournament, wallet ledger, storage audit and persistent notification.

Go match→verified result→Nakama RPC→leaderboard + wallet + notification

IAP receipt validation and social OAuth require external provider credentials; this local build demonstrates the Nakama APIs and marks those integrations as configuration-gated.

Architecture

Port 4001 is a Go gateway. It serves the web client, reverse-proxies Nakama HTTP and WebSocket traffic, and hosts the authoritative game server.

Browser / WebViewHTML5 + nakama-js
Go :4001static + proxy + game server
Nakama :7350auth · social · economy · matches
PostgreSQL :5432Nakama persistence

Nakama's console runs at port 7351. Local demo login: admin / a473e6bf26e7c40ff99d2c43. The console SPA keeps its own origin, so /console redirects there.

API boundaries — what is deliberately not faked

configure IAP receipt validation — needs Apple/Google credentials and a validation endpoint. The store purchase demonstrates Nakama's wallet ledger, not a real receipt.

configure Social provider auth — Apple, Google and Facebook login need provider client IDs/secrets. Device, custom and email auth are live.

not in this build Achievements / stats APIs — not present in this Nakama version. The showcase does not invent a fake endpoint; storage + RPC patterns cover similar needs.

separate origin Nakama console — its SPA expects port 7351. Use the redirect above; it is not embedded under 4001.
